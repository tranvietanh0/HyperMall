# HyperMall Refactor Contract Matrix

This document records the main frontend/backend contract drifts found during the refactor and the source-of-truth decisions applied in the current worktree.

| Area | Previous drift | Current source of truth | Status | Evidence |
| --- | --- | --- | --- | --- |
| Avatar upload | Frontend sent `multipart/form-data` with `file`; backend expected `avatarUrl` request param. | Backend controller contract wins. `userService.uploadAvatar` now posts `avatarUrl` params and returns `User`. | Aligned | `frontend/hypermall-web/src/services/user.service.ts`, `backend/user-service/src/main/java/com/hypermall/user/controller/UserController.java` |
| Shipping methods | Frontend called `GET /shipping/methods`; backend only exposed `POST /shipping/calculate`. | Backend shipping API wins. `orderService.getShippingMethods` now calls `/shipping/calculate` and maps `ShippingOptionResponse` into the frontend shipping selector model. | Aligned | `frontend/hypermall-web/src/services/order.service.ts`, `backend/shipping-service/src/main/java/com/hypermall/shipping/controller/ShippingController.java`, `backend/shipping-service/src/main/java/com/hypermall/shipping/dto/response/ShippingOptionResponse.java` |
| Cart item identifiers | Frontend typed cart item ids as `number`; backend uses `String` UUID-style ids. | Backend cart DTO wins. Frontend cart item ids are now typed as strings where cart state mutates them. | Aligned | `frontend/hypermall-web/src/types/order.types.ts`, `frontend/hypermall-web/src/store/slices/cartSlice.ts`, `backend/cart-service/src/main/java/com/hypermall/cart/dto/CartItemResponse.java` |
| Order tracking/order items | Frontend expected a separate `OrderTracking` model and order item fields `price` / `subtotal`; backend returns `OrderDetailResponse` with item fields `unitPrice` / `totalPrice`. | Backend order DTO wins. Frontend order types/pages now follow the backend order detail payload shape. | Aligned | `frontend/hypermall-web/src/services/order.service.ts`, `frontend/hypermall-web/src/types/order.types.ts`, `frontend/hypermall-web/src/pages/Order/OrderDetailPage.tsx`, `frontend/hypermall-web/src/pages/Order/OrderListPage.tsx`, `backend/order-service/src/main/java/com/hypermall/order/controller/OrderController.java`, `backend/order-service/src/main/java/com/hypermall/order/dto/OrderDetailResponse.java`, `backend/order-service/src/main/java/com/hypermall/order/dto/OrderItemResponse.java` |
| Profile update boundary | `ProfilePage` called `api` and `localStorage` directly instead of going through domain services. | Frontend service boundary wins. `ProfilePage` now routes profile/password/address updates through `userService` and `authService`. | Aligned | `frontend/hypermall-web/src/pages/Profile/index.tsx`, `frontend/hypermall-web/src/pages/Profile/components/ProfileInfoTab.tsx`, `frontend/hypermall-web/src/pages/Profile/components/ProfilePasswordTab.tsx`, `frontend/hypermall-web/src/services/user.service.ts`, `frontend/hypermall-web/src/services/auth.service.ts` |
| Admin route composition | `App.tsx` and `AdminRoutes.tsx` both defined admin route trees. | `AdminRoutes.tsx` wins as the single source, and `App.tsx` now renders from it. | Aligned | `frontend/hypermall-web/src/App.tsx`, `frontend/hypermall-web/src/routes/AdminRoutes.tsx` |

Environment note: backend runtime verification could not be executed here because Maven is unavailable in this environment. Frontend verification was completed with targeted tests, lint, and production build.
